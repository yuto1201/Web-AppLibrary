# 机の上の工作室 — サイトの方向の設計

ステータス: 下書き（侑斗さんの確認待ち）
作成日: 2026-11-14
調査の記録: Tool-UI-Design の `projects/yuto/2026-11-14-applibrary-direction/report.md` と `knowledge/references/indie-app-showcase-sites.md`

## 1. 意図と理由

AppLibrary は、侑斗さんが個人開発したアプリを**すべて**紹介するサイト。アプリは特定のテーマでまとまっていない。共通しているのは作り手の考え方「遊び心のあるアプリ」で、サイトにシールや 3D を入れているのはそのため。

侑斗さんが困っていること（2026-11-14）:

- 一貫性が足りない。
- アプリの紹介サイトとして見にくい。
- 色や見せ方が面白くない。

調べて分かった原因:

1. トップ（空色のポスター）とアプリのページ（アプリごとの専用の製品サイト）が別の世界になっている。
2. 一覧のカードの色にアプリの意味がない。色を順番に塗っていて、SimplePomo と花島がどちらも緑。各アプリの色は `src/lib/app-tone.ts` に決まっているのに使っていない。
3. カードに値段と入手先が出ていない。
4. アプリを見る手段がトップに 3 つ重なっている（冒頭のシール、カード、「A LITTLE CLOSER」の画面のぞき）。
5. 遊び心の道具（シール、青い立体の輪、hello のバッジ、鉛筆のメモ、降るフッター）が 1 つの世界の部品になっていない。
6. 飾りの英語の見出しが多く、声がいくつもある。Notes がサイトの模様替えの記録で、アプリの話がない。

参考サイトで繰り返し見えた答えは「**器は統一、色は中身**」「**世界観は 1 つ**」「**重い演出は 1 か所**」「**アプリのページの並びは共通**」。

## 2. 目標・しないこと・失敗とみなすこと

目標:

- どのページも「同じ机の上にある」と分かる。トップからアプリのページへ行っても、別のサイトに来たと感じない。
- X などから来た人が、トップの最初の 1〜2 画面で、どんなアプリが何本あって、それぞれ何をするか、いくらか、どの機種で動くかを拾い読みできる。
- 色を見ればどのアプリか分かる（アプリの色が、カード・シール・アプリのページ・降る物でつながる）。

しないこと:

- アプリのページの中身（専用の構成・文章・画面のギャラリー）を作り直さない。
- 検索・絞り込み・モーダルは足さない（アプリが 10 本を超えたら見直す。今の `top.md` と同じ）。
- 法務とサポートのページを遊ばせない。

失敗とみなすこと（動いていても）:

- 遊び心を足した結果、アプリの名前・値段・対応機種・入手先が見つけにくくなる。
- 演出が重くなり、スマホで最初の表示が遅くなる。
- 架空の数字や実績を書く（利用者数、評価など）。

## 3. 制約

- Next.js の静的出力（`output: "export"`）、Cloudflare Pages。サーバー・DB・解析なし。
- CSP は `script-src 'self'`。外の CDN から読まない。three.js と cannon-es は npm から束ね、フッターが近づいてから読む。
- `AGENTS.md` と `CLAUDE.md` の決まり: `.reveal` などスクロール連動は使わない、className を DOM へ直接書かない、`<html>` の `data-*` を初回から付ける、絶対パス、`tokens.css` のトークン名は変えない。
- `prefers-reduced-motion` では自動の動きを止める。ライトとダークの両方で、実際の配色で axe の `color-contrast` を通す。
- App Store のバッジを使うなら Apple の決まりどおり（1 つのレイアウトに 1 つ、高さ 40px 以上、傾けない・動かさない・改変しない、言語ごとの版）。シールに混ぜない。
- 今ある URL とページ内の目印は、どれも変えない・消さない。App Store Connect にどれを登録したかはリポジトリから分からないため。サポートの導線は、花島が `/apps/flower/support/`、ほかのアプリは `https://app.yutodev.com/#contact`。トップを組み替えても `#contact` の連絡先は必ず残す。プライバシーは `/apps/<slug>/privacy/`。

## 4. 考えた案

### 世界観

| 案 | 内容 | 結果 |
|---|---|---|
| A. 机の上の工作室 | 東京の小さな個人開発室の机。アプリは机に貼るシールとカード | **採用**（侑斗さん、2026-11-14）。机・シール・鉛筆の字は今のサイトの持ち物で、作り直しが少ない |
| B. おもちゃ箱 | アプリをおもちゃとして並べるカタログ | 不採用。トップの作り直しが大きい |
| C. 静かな器 | 落ち着いた一覧、主役はアイコン | 不採用。サイトとしての遊び心が弱い |

### アプリのページのそろえ方

| 案 | 内容 | 結果 |
|---|---|---|
| ① 共通の枠を足す | 中身はそのまま。上に共通の帯、下に共通の情報のまとまり | **採用**（侑斗さん、2026-11-14） |
| ② 全アプリ同じ型に作り直す | 1 つのひな形にアプリの色と画面を流し込む | 不採用。今の専用ページ（約 2,100 行）を作り直すことになる |
| ③ 今のまま | トップと一覧だけ直す | 不採用。別の世界に見える問題が残る |

## 5. 決めたこと

### 5.1 世界観: 机の上の工作室

- サイト全体を「東京の小さな個人開発室の机」に見立てる。どのページも同じ机の面（紙）の上にある。
- 世界の部品は 4 つに絞る。
  1. **紙**: 机の面。ページの地。
  2. **シール**: アプリそのもの。アプリのアイコンのシールは、トップの机とアプリのページの帯の両方に出る。文字のシール（Swift・Tokyo・一人制作）は作り手のラベルとして机に残す（Claude の判断）。
  3. **鉛筆のメモ**: Klee One の手書きの一言。作り手の声。
  4. **机に積もる物**: ページの最後に降って積もる 3D（試作の「降るフッター」）。3D はここ 1 か所だけ。
- この 4 つに入らない飾りは外す（Claude の判断）。今の青い立体の輪、黄色の「hello.」の丸いバッジ、星やアスタリスクの飾りなど。

### 5.2 器と色

- **器（全ページ共通）**: 机の面の色、カードの形（角丸と枠線）、書体（今の Inter・JetBrains Mono・Klee One）、余白。
- **色（アプリが持つ）**: 各アプリの色を、カード・シールの縁・アプリのページの帯・降る物に使う。
  - **アプリの色は、アイコンとそのアプリの専用ページの主な色を正とする**（Claude の判断）。今の `app-tone.ts` の値は、色でアプリを見分けられない（CafLog・PayCycle・SimplePomo の wash がほぼ同じベージュ、Dev-Tools と花島がほぼ同じ淡い青）。また専用ページともずれている（SubLog は app-tone がラベンダー、ページとアイコンは青 `#087bf4`。CafLog は app-tone がコーヒー色、ページはオレンジとピンク）。
  - だから `app-tone.ts` の値は作り直してよい。並べたときに 6 色が見分けられ、ライト・ダークでコントラストを満たすこと。値を変えたら `app-page.css` の同じ hex、テスト、registry の `color`・`accent` もそろえる。具体の値は試作で決める。
- サイト自体の色は、紙・インク・アクセント 1 つに減らす。どの色をサイトの色にするか（今の空色を残すか、紙らしい色に戻すか）は試作で決める（Claude の判断で、試作で 2 案を見せる）。
- 今のパステルの順番塗り（緑・ラベンダー・黄・青）はやめる。これは `docs/design/top.md` の「パステルの作品カード」を置き換える。

### 5.3 トップの構成

上から:

1. **Nav**: 今のまま（ブランド、アンカー、言語・テーマ）。
2. **Hero**: 机とシール。その下に「誰が・何を作っているか」の 1 行と CTA。大きな装飾の文字「APP LIBRARY」は残すかどうかを試作で決める。青い輪は外す。
3. **一覧（App Library）**: アプリの色のカードを 2 列（スマホは 1 列）。最初の画面か、すぐ下に見える。
4. **作り手**: 今の「BEHIND THE APPS」を、作り手の紹介として短くする（どこで・何で・どんな考えで作っているか）。
5. **アプリの更新**: 今の Notes を、アプリの話だけにする（5.6）。
6. **連絡**: X・GitHub。
7. **フッター**: 降って積もる物の上に、奥付と法務へのリンク。

「A LITTLE CLOSER」（`AppSpotlight` の画面のぞき）は、カードとアプリのページの画面のギャラリーと役目が重なるので、トップから外す（Claude の判断。侑斗さんが残したければ残す）。

### 5.4 一覧のカードの中身

全アプリ同じ並び。データはすべて今の registry から取る（新しい欄は足さない）。

- アイコン、名前、1 行（`tagline`）
- 分類（`category`）
- 対応機種（`platforms`）
- 値段（`price`。例「無料」「無料・買い切りの Pro あり」）。**App Store で公開中のアプリ（`appStoreUrl` がある）だけ出す**。未公開のアプリ（今は SimplePomo・花島）は、予定の値段と版を出さない（Claude の判断。`app-page.md` の「花島の価格は登録前のため書かない」と、「事実でないことを書かない」に合わせる）
- 状態（`status`。リリース済みは出さず、β・α・終了だけ札で出す）
- カード全体がアプリのページへのリンク。App Store への直接のリンクはカードに置かない（1 つのカードにリンクを 2 つ重ねないため。入手はアプリのページで）

最初の実画面（今のカードの上半分）は残す。アプリの色の面に載せる。

### 5.5 アプリのページの共通の枠

中身（各アプリの専用部分と、Dev-Tools の共通ひな形）はそのまま。前と後ろに共通の部品を足す。

- **上の帯（共通）**: 机の紙の細い帯。「← AppLibrary」、そのアプリのシール（小）、アプリ名。帯の縁かシールの縁にアプリの色。
- **下のまとまり（共通）**: 「このアプリについて」として、値段・版（`version`）・対応機種・状態・入手先（App Store）・サポート・プライバシー・利用規約（あるアプリだけ）。値段・版・入手先は、カードと同じく公開中のアプリだけ出す。サポートのリンク先は 3 章のとおり（花島は専用のサポートのページ、ほかは `#contact`）。その下に「ほかのアプリ」（残りのアプリのカードを小さく）。
- 各専用ページが今持っている、戻るリンク・法務へのリンクと重なる部分は、共通のまとまりに寄せて片方を消す。どれを消すかはページごとに実装で決める。
- 専用ページが保存テーマを無視して明るい配色を保つもの（CafLog など）は、そのまま。共通の帯とまとまりは、そのページの明るさに合わせる。
- 法務・サポートのページは、上の帯だけを付ける（落ち着いたまま）。

### 5.6 アプリの更新（今の Notes）

- アプリの話だけを載せる: リリース、新しい機能、サポートの知らせ。
- 今の 5 件（サイトの模様替え）はトップから外す。サイトの変更の記録は奥付か GitHub に任せる。
- 中身は事実だけ。日付と出来事は侑斗さんの確認を取ってから載せる（registry の `releaseDate` など、リポジトリにある事実から下書きを作るのはよい）。

### 5.7 声

- 日本語を主にする。飾りの英語の見出し（「LITTLE APPS. LOTS OF POSSIBILITIES.」「PICK. MOVE. PLAY.」「TAKE A CLOSER LOOK」「BEHIND THE APPS」「SAY HELLO」）は減らす。英語の表示（EN）のときは英語の文に切り替わる今の仕組みはそのまま。
- 作り手の声は鉛筆のメモ（Klee One）に寄せる。

### 5.8 降って積もるフッター

- 今の試作（`claude/spike-falling-footer` ブランチ、未コミット）をもとにする。
- 降る物の色はアプリの色（5.2）にする。物の形（角の丸い箱と球のままか、アプリのアイコンの面を持つ板にするか）は試作で決める。
- フッターが近づいてから three.js と cannon-es を読む。動きを減らす設定では、積もった後の 1 枚だけ。

## 6. 作る人に任せること

- 机の紙の色の具体的な値、カードの角丸・枠線の太さ、帯の高さ。ライトとダークのコントラストを満たすこと。
- 共通の帯とまとまりを、既存の各専用ページにどう差し込むか（共通の部品を作って各ページから呼ぶなど）。
- 「ほかのアプリ」のカードの大きさ。
- Issue の分け方と順番（目安は 7 章）。
- 降る物の数と物理の細かい値。

## 7. 進め方

試作を先に作り、侑斗さんが見て決めてから実装に入る。試作の結果に関係しない部分（カードの中身など）も、見た目が試作で変わるので先に実装しない（Claude の判断）。

1. Tool-UI-Design で試作する（Tool-UI-Design の案件として。`job.md`・`report.md` を書く）: トップ（5.1〜5.4、5.8）と、アプリのページ 1 つ（CafLog）の共通の枠（5.5）。ライト・ダーク、パソコンとスマホの幅。
2. 侑斗さんが試作を見て、サイトの色・6 つのアプリの色・装飾の文字・降る物の形を決める。
3. Web-AppLibrary で Issue に分けて実装する。目安:
   1. カードをアプリの色に、中身をそろえる（5.2・5.4）
   2. トップの構成と飾りの整理、声（5.1・5.3・5.7）
   3. アプリのページの共通の帯とまとまり（5.5）
   4. アプリの更新（5.6）
   5. 降って積もるフッター（5.8）
4. 決めたことは `docs/design/top.md` と `docs/design/app-page.md` に反映し、置き換えた方針を `docs/decisions/` に残す。

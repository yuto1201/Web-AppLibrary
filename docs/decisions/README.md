# Architecture Decision Records (ADR)

ステータス: 確定
最終更新日: 2026-05-16

重要な設計判断を「いつ・なぜ・何を選んだか」の形で時系列に記録する場所。

---

## ADR とは

「決定の事実」と「その背景・代替案・影響」を、後から読んでも判断の妥当性を再評価できる形で残す軽量フォーマット。
本プロジェクトでは下記の章立てを採用する:

```
## 背景
## 決定
## 検討した代替案
## 影響
```

ファイル名: `YYYY-MM-DD-<topic>.md`(決定が下された日付を先頭に置いて時系列ソート)。
ステータス値: `提案中` / `採択` / `撤回` / `上書き`。

「上書き」された ADR はファイルを削除せず残し、新しい ADR の `関連:` セクションから参照する。

---

## いつ ADR を書くか

- 構造的な選択(フレームワーク採用、データフロー変更、認証方式など)
- 後で「なぜこうしたか」を尋ねられそうな判断
- 複数の妥当な選択肢から 1 つを選んだとき

逆に、ローカルな実装テクニックや一時的な workaround は ADR にしない(コードコメント or `docs/apps/<slug>.md` のノウハウ節へ)。

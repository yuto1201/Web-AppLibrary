# Next.js 化と Vercel 移行

ステータス: 上書き（配信先のみ。Next.js の静的出力は継続）
日付: 2026-08-31
関連: 2026-05-16-docs-restructure

配信先は [2026-09-27 の Cloudflare Pages 判断](2026-09-27-cloudflare-pages-migration.md) が上書きする。以下は移行時点の記録。

---

## 背景

素の HTML / CSS / JavaScript による静的サイトとして Cloudflare Pages で運用してきたが、次の課題があった。

- **掲載カバー率が低い**: `~/Documents/Xcode` に 10 本以上あるアプリのうち、掲載は 2 本のみ
- **アプリ追加の手数が多い**: `apps/_template/` を手動コピーし、`index.html` と `privacy.html` を書き換え、`registry.js` にも追記する必要があった。同種のファイルが増えるほど重複が膨らむ
- **スコープが iOS 限定**: `<title>` も `registry.js` の `platform` も iOS 前提で、他プラットフォームを掲載できない
- **多重公開**: Cloudflare Pages と GitHub Pages の両方で同じ内容を配信していた
- **型がない**: `registry.js` の記述ミスは実行時まで検出されなかった

## 決定

Next.js 16 の静的出力へ移行し、Vercel で配信する。

- `output: "export"` を採用し、サーバー処理を持たない構成を維持する
- `src/data/registry.ts` を zod で検証し、スキーマ違反はビルドで落とす
- `platform` を `platforms` 配列へ変更し、プラットフォーム軸のフィルタを追加する
- アプリ詳細ページとプライバシーページを registry から静的生成する
- デザインシステム CSS 1,712 行は無改変で流用する
- GitHub Pages の公開を終了し、配信先を Vercel 一本に集約する

## 検討した代替案

**現構成のまま Vercel へ移すだけ** — Vercel は静的サイトをそのまま配信できるため、移行自体に Next.js 化は不要だった。しかし手動コピーによるページ追加という主要課題が残るため採用しなかった。

**Cloudflare Pages のまま Next.js 化** — 配信は可能だが、Web-Template の構成に寄せる方針と揃わないため採用しなかった。

**デザインごと作り直す** — 既存デザインシステムには完了済みの設計計画 2 件（計 1,686 行）が紐付いており、品質上の問題も見当たらなかったため、保全を選んだ。

## 影響

- ビルド工程と依存パッケージが増えた。`AGENTS.md` の「フレームワーク追加禁止」条項はこの決定に合わせて改訂した
- `node_modules` が iCloud 同期下に入る。`~/Documents` は同期領域のため、同期中は git 操作が遅くなる既知の副作用がある
- 静的出力は `/_next/...` の絶対パスを使うため、サブディレクトリ配信はできない。GitHub Pages を再開する場合は `basePath` の設定が必要
- 旧サイトの個別ページにあった手書きの機能カードは未移植。registry の `features` タグのみ表示される

追記（2026-09-01）: Issue #14 の後続作業で `features` をアイコン・見出し・説明へ構造化し、共通カードとして移植した。上記は移行時点の記録として残す。

## 移行時に判明した不具合

移植の過程で 4 件の不具合を修正した。うち 1 件は旧サイトから存在していたもの。

- `.reveal` の表示クラスは `.in` が正。誤ったクラス名ではカードが表示されなかった
- className の DOM 直接操作は React の再描画で失われる。`useReveal` フックで状態として保持する形へ変更
- 保存値が無い初回訪問で `<html>` の `data-*` 属性が付かず、既定スタイルが適用されなかった
- hero の eyebrow が `profile.tagline` と重複表示されていた（旧サイトからの不具合）
